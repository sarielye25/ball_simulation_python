## 数据结构与发布规则（已确认）

```text
model_training/data/<group_id>/
  group.json                         稳定组 ID、名称、说明及来源
  runs/<run_id>/
    run.json                         唯一发布清单：协议版本、身份、状态、列、单位、容差、split 定义、文件引用及完整性信息
    datasets/<split_id>.csv          本次运行的不可变样本快照；含 row_id、组别、输入和目标
    evaluations.csv                  各 update / split / scope 的指标，含 train 与 validation
    baselines.csv                    基线指标（若适用）
    evaluation_events.csv            评估及学习率事件（若适用）
    batches.csv                      训练批次记录（Qt 可按需读取）
    checkpoints/index.json          训练侧模型索引和选择结果
    checkpoints/update_*.pt         训练、恢复用；Qt 不打开
    predictions/<checkpoint>/<split_id>.csv  不可变逐样本预测；以 row_id 关联快照
    termination.json                 结束或中止详情（若存在）
```

- 每个训练组一个稳定 `<group_id>`，每次训练一个新 `<run_id>`；包内只用相对路径，数据根目录可配置，搬移后仍可读取。`group.json` 存组级信息，`run.json` 是 Qt 的唯一运行入口。
- `evaluations.csv` 保留现有长表思路：同一文件存 train 和 validation，以 `split` 列区分，Qt 在内存中筛选。未来增加验证数据组时，以清单声明的新 `split_id` 和相应样本、预测文件扩展，不要求新增 Qt 图表代码中的硬编码分支。具体 split 类型与展示策略随上层结构讨论确定。
- 数据快照与预测文件发布后不可修改；预测文件至少有 `row_id` 和预测列，Qt 根据 `row_id` 与快照关联并检查唯一性、覆盖范围及身份。模型 `.pt` 仅供训练侧恢复或生成预测，Qt 不依赖训练模块。
- `evaluations.csv` 等训练期间追加的日志，由 `run.json` 记录**已提交前缀的字节长度和 SHA-256**；Qt 只读该长度内的完整 CSV 行并验证哈希。未发布的尾部不属于当前快照，不得展示。不可变文件记录完整文件哈希。清单还需定义编码、表头和字段约束。
- 一次发布顺序：先完成本次评估及预测写入、校验所有引用和 CSV 行边界，再把完整新清单写入同目录临时文件，最后原子替换 `run.json`。Qt 读到旧清单或新清单，不应读到半份清单；失败时保留上一份完整清单。训练只能追加日志的尾部，不得改动已提交前缀。发布与读取期间需按清单中的长度和哈希检查一致性。
- 开始训练时创建组和 run；每次评估/checkpoint 后发布一次；结束或中止时发布状态。异常信息不能通过破坏旧清单来记录；没有结束记录时显示未完成。默认发布 train / validation，保留的 test 数据不进入查看范围。
- 统一协议需明确版本、组/运行身份、状态、split 定义、列与单位、容差、指标、基线、事件及文件完整性。旧 v1/v2 实验通过导入工具迁移；导入时保留原件，不覆盖历史记录。

## Qt 上层结构（已确认）

- 数据流：`run.json` 及其文件 → 只读读取层（校验与协议版本适配）→ 稳定的内存数据对象 → 纯内存分析/筛选 → 图表与表格。窗口选择由控制器协调，耗时读取与计算交给后台任务。
- 读取层负责浏览组和 run、读取一次已发布快照、校验身份/路径/哈希/字段/关联，并将不同文件版本转换到同一内存契约；只在这一层理解 CSV 布局、提交前缀和存储版本。不能让图表依赖训练组源码或具体文件路径。
- 内存契约应表达组/run 身份与状态、按 ID 描述的 split（含显示名和用途）、指标记录、checkpoint、样本、预测及字段元数据。数据对象要明确缺失结果；具体 Python 类型和字段签名在实现前定义并测试。
- 内存数据模型只规定对象的结构和含义，不承担文件读取、计算或绘制；它不是缓存。
- 内容生成分为两条独立路径：曲线分析按 split/checkpoint/metric 准备曲线点、标签及单位；失败分析以 `row_id` 关联样本和预测、应用容差，准备摘要及失败行。两者只接收内存对象，不打开文件。
- Qt 图表接收准备好的曲线，表格接收准备好的摘要及失败行；绘制和交互留在视图层。控制器协调用户选择，后台任务处理耗时读取与计算，避免阻塞窗口。
- 新增验证 split 应由清单、内存对象和选择器驱动，通用分析与绘图按 split ID 工作。若以后只改变存储布局或协议版本，优先新增/修改读取适配并保持内存契约稳定；若新增结果的语义或展示形式，则相应扩展内存契约和分析/界面，不承诺零修改。
- 用契约测试约束读取层输出和分析层输入；至少验证不同 split、协议版本变化、缺失数据及损坏文件不会把存储细节泄漏到图表。
- 首版忽略缓存；只有实际使用中出现明显加载或切换问题时才回来评估和解决。若届时引入缓存，必须随已发布 `run.json` 的版本/内容变化失效。
