Qt 训练结果查看器：GitHub 开源代码参考
检索日期：2026-09-27
对应计划：qt_building_plan.md

结论
已有开源代码可以覆盖交互曲线、Qt 表格模型、排序过滤、后台任务和 UI 测试。
本次检索未确认有直接满足整份计划的完整训练结果查看器。建议以 PySide6 +
PyQtGraph 为基础，参考下面的官方示例，复用本项目已有数据与推理模块。
优先顺序：1、2、3；4、5 是后台任务实现的可选参考，不必同时引入。

1. PyQtGraph：最直接可用的绘图依赖（计划第 2、3 节）
仓库：https://github.com/pyqtgraph/pyqtgraph
许可证：核心 LICENSE.txt 为 MIT；仓库中部分色图数据有独立许可证。
许可证原文：https://github.com/pyqtgraph/pyqtgraph/blob/master/LICENSE.txt

可复用代码：
共享坐标范围：
https://github.com/pyqtgraph/pyqtgraph/blob/master/pyqtgraph/examples/linkedViews.py
鼠标十字线与数值显示：
https://github.com/pyqtgraph/pyqtgraph/blob/master/pyqtgraph/examples/crosshair.py
checkpoint、最后评估位置、学习率下降位置的标记：
https://github.com/pyqtgraph/pyqtgraph/blob/master/pyqtgraph/examples/InfiniteLine.py
散点交互参考：
https://github.com/pyqtgraph/pyqtgraph/blob/master/pyqtgraph/examples/ScatterPlot.py
图例实现参考：
https://github.com/pyqtgraph/pyqtgraph/blob/master/pyqtgraph/graphicsItems/LegendItem.py

适配要点：linkedViews.py 已展示 setYLink/setXLink，适合训练/验证双图。
crosshair.py 用 int(x) 索引等间距数组；本项目 optimizer update 不保证连续，
必须按实际 update 数组寻找对应评估点，并补充组名、样本数和指标单位。
示例中的随机数和平滑数据仅用于演示，不能用于构造本项目真实曲线。
仍需实现指标切换、组显示开关、空组缺口、通过率 0–100% 和重置视图。

2. Qt for Python 官方源码与示例：表格、过滤与线程（计划第 5、8、9 节）
仓库：https://github.com/pyside/pyside-setup
QAbstractTableModel + QTableView 示例：
https://github.com/pyside/pyside-setup/blob/dev/examples/external/pandas/dataframe_model.py
QSortFilterProxyModel 示例：
https://github.com/pyside/pyside-setup/blob/dev/examples/widgets/itemviews/basicfiltermodel/basicsortfiltermodel.py
线程信号示例目录：
https://github.com/pyside/pyside-setup/tree/dev/examples/widgets/thread_signals

许可证：上述已读取的 dataframe_model.py 和 basicsortfiltermodel.py 文件头为
LicenseRef-Qt-Commercial OR BSD-3-Clause，可按 BSD-3-Clause 条件复用示例。
PySide6/Qt 库本身与其他源码文件的许可证需分别查看，不能把整个仓库当作 BSD。
https://github.com/pyside/pyside-setup/tree/dev/LICENSES

适配要点：DataFrame 示例的 DisplayRole 返回字符串，直接照搬不能保证数值排序。
应提供独立的原始数值排序角色或实现 lessThan；显示舍入与失败判定必须分离。
增加组、失败类型、breakaway、row ID 的组合筛选；导出全部代理模型筛选行。
pandas 只是示例的数据后端，也可用现有 NumPy/记录数组，避免新增不必要依赖。
dev 分支的过滤示例使用 QRangeModel；实现时选与安装版本匹配的 Qt release/tag，
保留计划要求的 QAbstractTableModel，不直接依赖开发分支的新 API。

3. pytest-qt：Qt 交互与异步信号测试（计划第 10 节）
仓库：https://github.com/pytest-dev/pytest-qt
用法与兼容性：https://github.com/pytest-dev/pytest-qt/blob/master/README.rst
许可证：MIT。
https://github.com/pytest-dev/pytest-qt/blob/master/LICENSE

可直接使用 qtbot 模拟鼠标/键盘，waitSignal/waitSignals 等待后台结果。
README 明确支持 PySide6。适合验证 checkpoint 切换、排序过滤、过期结果丢弃、
错误提示及窗口关闭流程；测试期使用，不必作为查看器运行依赖。
实际桌面的高 DPI、中文字体和窗口布局仍需人工验收。

4. superqt：可选的后台 worker 工具（计划第 8、9 节）
仓库：https://github.com/pyapp-kit/superqt
线程工具源码：
https://github.com/pyapp-kit/superqt/blob/main/src/superqt/utils/_qthreading.py
许可证：BSD-3-Clause。
https://github.com/pyapp-kit/superqt/blob/main/LICENSE

可复用 thread_worker/create_worker 的结果、错误与完成信号，或参考
new_worker_qthread 的 QObject.moveToThread 与生命周期连接方式。
源码使用 qtpy 抽象层；如引入该依赖，需明确选择 PySide6 后端。
其主要 worker 基于 QRunnable/QThreadPool，不全部采用专用 QThread。
取消是协作式的，普通长时间函数不会因 quit 自动中断；应在推理批次之间检查取消。
请求编号、过期结果丢弃、有限缓存与安全关闭仍需本项目实现。
若只需要一个后台推理 worker，直接使用 PySide6 也足够。

5. PySide6 Worker Pattern Demo：小型线程生命周期参考（计划第 9 节）
仓库：https://github.com/asilichenko/pyside6-worker-pattern-demo
说明：https://github.com/asilichenko/pyside6-worker-pattern-demo/blob/master/README.md
控制器源码：
https://github.com/asilichenko/pyside6-worker-pattern-demo/blob/master/worker_pattern_demo/controllers/main_window_controller.py
许可证：MIT。
https://github.com/asilichenko/pyside6-worker-pattern-demo/blob/master/LICENSE

展示 QThread 子类、progress/result/error 信号、requestInterruption 和清理连接。
适合作为理解线程生命周期的小示例，不能原样当成计划要求的完整后台层。
已读控制器在关闭窗口时 wait 最多 3000 ms，超时后仅记录警告；这可能阻塞 UI，
也不足以证明线程已安全退出。需改成符合本计划的关闭流程，并加入请求编号。

本项目仍需自己实现的部分
- run.json、CSV、termination.json 与 checkpoint index 的数据契约及错误校验。
- 标签 SHA-256、行数和稳定 row ID 校验；禁止读取保留测试集。
- 使用每个 checkpoint 保存的 normalization、run_config 和可信权重加载方式。
- 两输出严格小于容差的联合通过率、互斥运动组、重叠 breakaway 切片及失败严重度。
- selected/last 区分、真实停止原因、确定性总结、真实/演示标志。
- CPU 推理、缓存、请求取消、过期结果丢弃和筛选后完整 CSV 导出。
这些规则应复用现有 data.py、metrics.py、checkpoints.py、neural_network.py，
而不是从通用 GUI 项目复制一套训练逻辑。
